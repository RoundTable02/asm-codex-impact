# 사회복지 상담 AX Tool — MVP 기능 명세서

## 1. 프로젝트 개요

### 1.1 서비스 목적

사회복지사가 어르신과 전화 상담을 진행한 뒤 발생하는 반복적인 기록·정리 업무를 AI로 보조한다.

서비스는 다음 세 가지 핵심 업무를 지원한다.

**상담을 기록한다 → 기록을 문서로 바꾼다 → 다음 일을 놓치지 않게 한다.**

### 1.2 핵심 기능

1. 사용자가 업로드한 전화 상담 녹음 파일 전사(STT)
2. 상담일지 및 사례회의용 리포트 자동 생성
3. 위험신호·미해결 이슈 추출 및 다음 액션 추천

### 1.3 핵심 사용자

노인복지관, 노인맞춤돌봄서비스 등에서 상담·사례관리를 수행하는 사회복지사

### 1.4 MVP 제외 범위

이번 해커톤 버전에서는 아래 기능을 구현하지 않는다.

- 회원가입 / 로그인
- 기관별 권한 관리
- 실제 전화 연결
- 서비스 내 음성 녹음
- 실시간 통화 STT
- 외부 복지시스템 연동
- SMS / 카카오톡 알림
- RAG / Vector DB
- AI Agent
- 자체 위험도 예측 모델
- 실제 의료·법률적 판단
- PDF/HWP 자동 출력
- 복잡한 통계 대시보드

# 2. 핵심 처리 흐름

```text
서비스 접속
    ↓
내담자 등록 또는 기존 내담자 선택
    ↓
상담 종료 후 녹음 파일 업로드
    ↓
STT 결과 생성 및 저장
    ↓
상담자 전사문 확인·수정·저장 및 확정
    ↓
상담일지 초안 생성
    ↓
상담자 상담일지 확인·수정·저장
    ↓
상담일지 확정 및 후속 분석 요청
    ↓
위험신호·미해결 이슈·상태변화 추출 및 추천 Action 생성
    ↓
결과 저장 및 내담자 상담 이력에 누적
```

접속 시 회원가입이나 로그인은 요구하지 않는다. 등록된 내담자는 다시 등록하지 않고 선택한다.

전사문 확정과 상담일지 확정을 별도 단계로 처리한다. 상담일지 저장만으로 후속 분석을 실행하지 않으며, 상담자가 검토를 마치고 확정할 때 위험신호와 추천 Action을 생성한다.

## 기능

## 반환 정보

- 이름 또는 가명
- 출생연도 또는 나이

# 4. 내담자 등록

## 4.1 목적

상담 및 리포트를 특정 내담자 단위로 누적 관리한다.

## 입력 데이터

필수:

- 이름 또는 가명

선택:

- 출생연도
- 성별
- 특이사항 / 메모

예:

```text
이름: 김OO
출생연도: 1945
성별: 여성
메모: 독거 / 딸 부산 거주
```

## 저장 데이터

```json
{
  "id": 1,
  "name": "김OO",
  "birth_year": 1945,
  "gender": "F",
  "memo": "독거 / 딸 부산 거주"
}
```

## 제약

회원가입 기능이 없으므로 모든 내담자는 현재 서비스의 공용 데이터로 취급한다.

해커톤 데모에서는 실제 개인정보 대신 가명 데이터를 사용한다.

# 5. 내담자 상세 및 상담 이력 조회

## 5.1 목적

## 반환 정보

### 기본정보

- 이름
- 나이 또는 출생연도
- 메모

### 현재 상태 요약

AI가 최근 상담을 기준으로 요약한다.

예:

```text
현재 상태

건강
무릎 통증 지속

식생활
최근 식사 빈도 감소

가족
딸 타지역 거주
```

### 미완료 Action

```text

[보통] 다음 주 안부전화
```

```text
외출 빈도 감소

2026.08.03
무릎 통증 발생
```

## 기능

- 상담 녹음 파일 업로드
- 과거 상담 상세 조회
- Action 완료 처리
- 사례회의 리포트 생성

# 6. 기능 1 — 상담 녹음 파일 업로드 및 STT

## 6.1 목적

사회복지사가 직접 업로드한 기존 상담 녹음 파일을 전사문으로 변환한다.

## 입력 및 처리

사용자가 서비스 외부에서 준비한 상담 녹음 파일을 내담자 ID와 함께 업로드한다.

백엔드는 파일을 수신하여 해당 내담자의 새 상담 기록을 생성하고 STT를 실행한다.

서비스 내 녹음 기능은 제공하지 않는다.

## 처리 흐름

```text
사용자가 기존 상담 녹음 파일 선택
    ↓
Backend upload
    ↓
STT API
    ↓
Transcript
```

## 상태값

```text
UPLOADED
TRANSCRIBING
AWAITING_TRANSCRIPT_REVIEW
GENERATING_NOTE
AWAITING_NOTE_REVIEW
ANALYZING
DONE
FAILED
```

## 처리 상태 조회

상담 조회 API를 통해 현재 처리 상태를 반환한다.

| 상태 | 의미 |
| --- | --- |
| `UPLOADED` | 파일 업로드 완료 |
| `TRANSCRIBING` | STT 실행 중 |
| `AWAITING_TRANSCRIPT_REVIEW` | 전사문 확인·수정·확정 대기 |
| `GENERATING_NOTE` | 확정된 전사문으로 상담일지 초안 생성 중 |
| `AWAITING_NOTE_REVIEW` | 상담일지 확인·수정·확정 대기 |
| `ANALYZING` | 확정된 상담일지로 위험신호·미해결 이슈·상태변화·추천 Action 생성 중 |
| `DONE` | 후속 분석 결과 저장 완료 |
| `FAILED` | 처리 실패 |

STT 완료 후 전사문 검토를 기다리고, 전사문 확정 요청 시에만 `GENERATING_NOTE`로 전환한다. 상담일지 생성 후에는 다시 검토를 기다리고, 상담일지 확정 요청 시에만 `ANALYZING`으로 전환한다.

## STT 결과

```text
사회복지사:
요즘 식사는 잘하고 계세요?

김OO:
요새 무릎이 아파서 뭘 해먹기가 힘들어요.
라면 먹을 때가 많아요.

사회복지사:
병원은 가보셨어요?

김OO:
다음 주에 가야 하는데 혼자 가기가 힘들어요.
```

## 전사문 검토 및 확정

사용자는 `AWAITING_TRANSCRIPT_REVIEW` 상태에서 전사문을 조회하고, 필요한 경우 수정 API로 변경 내용을 저장한다. 전사문 저장만으로 분석을 실행하지 않는다.

검토를 마친 사용자가 전사문 확정 API를 호출하면 저장된 전사문을 확정하고 상담일지 초안만 생성한다. 수정할 내용이 없으면 원본 전사문을 그대로 확정할 수 있다. 위험신호와 추천 Action은 이 단계에서 생성하지 않는다.

전사문 확정 이후에는 전사문 수정을 허용하지 않는다. 생성된 상담일지는 다음 검토 단계에서 수정할 수 있으며, 별도의 재분석 기능은 제공하지 않는다.

# 7. 기능 2 — 상담 내용 구조화

## 7.1 목적

전사문을 단순 요약하는 것이 아니라 사회복지 업무에 필요한 정보 구조로 변환한다.

## 단계별 처리

1. 전사문 확정 후: 확정된 Transcript를 구조화해 상담 요약·주요 상담 내용·내담자 상태를 담은 상담일지 초안을 생성한다. 이 단계에서는 위험신호와 추천 Action을 생성하지 않는다.
2. 상담일지 확정 후: 상담자가 수정·확정한 상담일지를 기준으로 구조화 데이터를 갱신하고, 최근 상담 3~5건의 확정 기록과 비교해 후속 분석을 실행한다. 확정된 Transcript는 근거 확인에 사용한다.

수정 전 상담일지 초안이나 그 초안에서 추출한 상태를 그대로 후속 분석에 사용하지 않는다. 전사문과 확정 상담일지의 내용이 충돌하면 상담자의 수정 내용을 우선 반영하되, 근거가 불명확한 부분은 `확인 필요`로 처리한다.

## 출력

상담일지 초안 생성 단계에서는 다음 구조화 데이터를 저장한다.

```json
{
  "summary": "무릎 통증으로 외출 및 식사 준비에 어려움을 겪고 있음",
  "client_status": {
    "health": ["무릎 통증 악화"],
    "nutrition": ["식사 준비 어려움"],
    "emotion": [],
    "family": ["자녀 타지역 거주"],
    "housing": [],
    "social": ["외출 감소"]
  }
}
```

상담일지 확정 후 위 데이터를 갱신하고 다음 필드를 추가한다. 후속 분석 전에는 해당 필드를 생성하지 않아, 미생성 상태와 분석 결과가 없는 빈 배열을 구분한다.

```json
{
  "important_changes": [],
  "risk_flags": [],
  "unresolved_issues": [],
  "recommended_actions": []
}
```

## client_status 카테고리

MVP에서는 아래 6개 항목만 사용한다.

- HEALTH
- NUTRITION
- EMOTION
- FAMILY
- HOUSING
- SOCIAL

# 8. 기능 3 — 상담일지 생성

## 8.1 목적

전화 상담 후 사회복지사가 직접 작성해야 하는 상담기록 초안을 생성한다.

## 출력 구성

### 상담 요약

```text
대상자는 최근 무릎 통증이 심해져 외출 및 식사 준비에
어려움을 겪고 있다고 이야기함.
```

### 주요 상담 내용

```text
- 최근 무릎 통증 악화
- 외출 빈도 감소
- 식사 준비가 어려워 라면 등으로 대체
- 다음 주 병원 방문 예정
- 혼자 병원에 가는 데 어려움 호소
```

### 내담자 상태

```text
건강
무릎 통증 악화

식생활
식사 준비 어려움

사회관계
외출 감소

가족
자녀 타지역 거주
```

## 검토·수정 및 확정

`AWAITING_NOTE_REVIEW` 상태에서 사용자가 상담일지를 확인하고 수정 API로 변경 내용을 저장한다. 수정할 내용이 없으면 초안을 그대로 확정할 수 있다.

상담일지 확정 API를 호출하면 저장된 내용을 확정하고 위험신호·미해결 이슈·상태변화·추천 Action을 생성한다. 단순 저장은 후속 분석을 실행하지 않는다.

AI 생성값은 확정 전까지 **초안**으로 취급한다. 확정 후에는 후속 분석 결과와의 일관성을 위해 상담일지를 수정하지 않는다.

# 9. 기능 4 — 지난 상담 대비 변화 감지

## 9.1 목적

이전 상담과 현재 상담을 비교해 내담자의 상태 변화 정보를 반환한다.

## 입력

이전 확정 상담 기록의 구조화 데이터

현재 확정 상담일지를 반영해 갱신한 구조화 데이터

상담일지 확정 후 후속 분석 단계에서 실행한다.

## 예

이전:

```text
식사: 정상
외출: 주 3회
무릎 통증: 경미
```

현재:

```text
식사: 하루 한 끼
외출: 거의 하지 않음
무릎 통증: 악화
```

## 출력

```text
이번 상담에서 확인된 변화

↓ 건강
무릎 통증이 이전보다 악화됨

↓ 식생활
정상 식사 → 하루 한 끼 수준으로 감소

↓ 사회활동
주 3회 외출 → 거의 외출하지 않음
```

## 변화 상태

```text
IMPROVED
UNCHANGED
WORSENED
UNKNOWN
```

Transcript에서 판단할 근거가 부족하면 반드시 `UNKNOWN` 처리한다.

# 10. 기능 5 — 위험신호 추출

## 10.1 목적

상담일지 확정 후, 확정된 상담일지와 전사문 근거를 바탕으로 추가 확인이 필요한 중요한 신호를 추출한다.

## Risk Category

MVP에서는 아래 카테고리를 사용한다.

```text
HEALTH
NUTRITION
EMOTION
ISOLATION
ABUSE
HOUSING
ECONOMIC
SAFETY
OTHER
```

## Severity

```text
LOW
MEDIUM
HIGH
```

## Risk 객체

```json
{
  "type": "NUTRITION",
  "severity": "MEDIUM",
  "description": "식생활 상태 추가 확인 필요",
  "evidence": "라면으로 먹을 때가 많아요."
}
```

## 반환 내용 예시

```text
⚠ 식생활 상태 확인 필요

"라면으로 먹을 때가 많아요."

AI 판단
최근 정상적인 식사를 준비하기 어려운 것으로 보이며
추가적인 확인이 필요합니다.
```

## 중요 원칙

AI가 질환·학대·자살위험 등을 확정적으로 진단하지 않는다.

잘못된 표현:

```text
우울증이 있음
```

허용 표현:

```text
정서 상태 추가 확인 필요

근거:
"요즘 아무것도 하기 싫어요."
```

# 11. 기능 6 — 미해결 이슈 추출

## 목적

상담일지 확정 후, 상담에서 문제가 언급됐지만 아직 해결되지 않은 사항을 추출해 별도로 관리한다.

예:

```text
미해결 이슈

- 병원 이동 방법 미정
- 식사지원 서비스 이용 여부 미정
- 다음 진료 결과 확인 필요
```

미해결 이슈는 이후 Action 생성에 활용한다.

# 12. 기능 7 — 다음 Action 추천

# 13. 기능 8 — 사례회의용 리포트

## 목적

하나의 상담이 아니라 특정 내담자의 여러 상담을 종합해 사례회의에서 사용할 수 있는 요약 자료를 만든다.

## 생성 요청

내담자 ID를 지정해 사례회의 리포트 생성 API를 호출한다.

## 입력

내담자의 최근 상담 기록 3~10건

-

현재 미완료 Action

-

현재 Risk

## 출력

### 1. 내담자 현황

```text
김OO / 81세 / 독거
자녀 타지역 거주
```

### 2. 최근 상태

```text
건강
무릎 통증이 최근 지속적으로 악화

식생활
최근 정상적인 식사 횟수 감소

사회활동
외출 빈도 감소
```

### 3. 주요 변화 Timeline

```text
8월 3일
무릎 통증 최초 확인

8월 21일
외출 감소

9월 4일
식사 어려움 확인
```

### 4. 현재 위험신호

```text
- 식생활 상태 추가 확인 필요
- 건강 상태 악화 여부 확인 필요
```

### 5. 지원 현황

```text

```

### 6. 미해결 이슈

```text
- 병원 동행 지원 여부

```

### 7. 회의에서 논의할 내용

```text
1. 병원 동행 서비스 연계 여부
```

`AWAITING_TRANSCRIPT_REVIEW` 상태에서만 전사문을 수정·저장한다. 분석은 실행하지 않는다.

## 상담일지 수정

```text
PATCH /consultations/{consultation_id}/counseling-note
```

`AWAITING_NOTE_REVIEW` 상태에서 사용자가 검토·수정한 상담일지를 저장한다. 후속 분석은 실행하지 않는다.

## 전사문 확정 및 상담일지 생성

```text

```

`AWAITING_TRANSCRIPT_REVIEW` 상태에서 저장된 전사문을 확정하고 상담일지 초안을 생성한다. 생성 완료 후 `AWAITING_NOTE_REVIEW`로 전환한다.

## 상담일지 확정 및 후속 분석

```text
POST /consultations/{consultation_id}/counseling-note/confirm
```

`AWAITING_NOTE_REVIEW` 상태에서 저장된 상담일지를 확정하고 위험신호·미해결 이슈·상태변화·추천 Action을 생성한다. 결과 저장 후 `DONE`으로 전환한다.

# 16. AI 처리 원칙

AI Prompt에는 아래 조건을 공통 적용한다.

1. 상담에서 확인되지 않은 사실을 생성하지 않는다.
2. 불명확한 정보는 `확인 필요` 또는 `UNKNOWN`으로 처리한다.
3. 의료적·법률적 진단을 수행하지 않는다.
4. 위험신호에는 가능한 경우 Transcript 근거를 함께 제시한다.
5. 다음 Action은 사회복지사의 최종 판단이 필요한 `추천`으로 표현한다.
6. 현재 상담뿐 아니라 최근 상담 상태와 비교해 중요한 변화를 추출한다.
7. 전사문 확정 후 구조화된 JSON으로 상담일지 초안을 생성한다. 위험신호와 추천 Action은 상담일지 검토·수정·확정 이후에 생성한다.
8. 후속 분석은 확정된 상담일지의 수정 내용을 반영한 구조화 데이터를 사용한다. 사례회의 자료도 확정된 상담 기록을 기반으로 생성한다.

# 18. 해커톤 데모 시나리오

사용자가 미리 준비한 두 개의 상담 녹음 파일을 같은 내담자에게 순서대로 업로드한다. 각 상담은 STT 결과 확인 → 전사문 수정·저장·확정 → 상담일지 초안 확인 → 상담일지 수정·저장·확정 → 위험신호·추천 Action 생성 순서로 진행한다.

## 첫 번째 상담

김OO 어르신이 다음과 같이 이야기한다.

```text
무릎이 조금 아프지만 아직 밖에는 자주 나간다.
식사는 잘 하고 있다.
```

AI 기록:

```text
건강
경미한 무릎 통증

식사
정상

사회활동
외출 유지
```

## 두 번째 상담

```text
요즘 무릎이 너무 아파서 거의 안 나가요.
밥 해먹기도 귀찮아서 하루에 한 번 먹을 때가 많아요.
다음 주 병원에 가야 하는데 혼자 가기 어려워요.
```

상담자가 두 번째 상담일지를 검토·수정하고 확정하면 AI가 다음 결과를 생성한다:

```text
⚠ 상태 변화

건강 ↓
무릎 통증 악화

식생활 ↓
정상 → 하루 한 끼

사회활동 ↓
외출 감소
```

그리고:

```text
다음 Action

[높음]
병원 동행 가능 서비스 확인

[높음]
식생활 상태 추가 확인

[보통]
병원 방문 이후 상태 확인
```

을 생성한다.

마지막으로 사례회의 리포트 생성 API를 호출하면 두 번의 상담 내용을 합쳐 내담자의 변화와 미해결 문제를 반환한다.

# 19. MVP 성공 기준

해커톤에서 아래 흐름이 끊기지 않고 작동하면 MVP가 완성된 것으로 본다.

```text
내담자를 등록할 수 있다.

↓

사용자가 기존 상담 녹음 파일을 업로드할 수 있다.

↓

업로드한 녹음 파일을 텍스트로 변환할 수 있다.

↓

사용자가 전사문을 검토하고 필요 시 수정·저장할 수 있다.

↓

사용자가 전사문을 확정하면 상담일지 생성을 시작한다.

↓

AI가 상담 내용을 구조화한다.

↓

상담일지 초안을 생성한다.

↓

사용자가 상담일지를 확인하고 수정·저장할 수 있다.

↓

사용자가 상담일지를 확정하면 후속 분석을 시작한다.

↓

지난 상담과 비교해 상태 변화 정보를 반환한다.

↓

위험신호와 미해결 이슈를 반환한다.

↓

다음 Action을 추천한다.

↓

Action을 완료 처리할 수 있다.

↓

여러 상담을 합쳐 사례회의 리포트를 생성할 수 있다.
```

## 제품의 핵심 메시지

**사회복지사는 어르신에게 집중하고,
AI는 상담 이후의 기록과 후속조치를 정리합니다.**
